# التشغيل على جهازك (On-device rendering)

الفكرة ببساطة: بدلا من أن يُصيَّر الفيديو على الخادم السحابي،
يُصيَّر على جهازك أنت، بموارده أنت. الوكيل لا يستطيع تشغيل
التصيير على هاتفك من هنا — لا توجد قناة أوامر إلى الهاتف،
وتطبيق Muse لا يستضيف خوادم MCP للمستخدم — لذلك التقسيم كالتالي:

- الوكيل يبني المشروع ويحزمه ويسلّمك رابط الحزمة.
- أنت تفك الحزمة على هاتفك وتشغّل `./render.sh`، ثم تبلّغ
  الوكيل بالنتيجة (نجح، أو رسالة الخطأ كما هي).

## الطريقة الموصى بها: حزمة التصيير (لا تحتاج git ولا خادم)

المتطلبات على الهاتف: تطبيق Termux، ثم داخله:

```
pkg install python ffmpeg
```

ثم فكّ الحزمة في مكان قابل للكتابة داخل مجلد Termux الرئيسي
(وليس على بطاقة SD — أندرويد يقيّد الكتابة عليها)، وادخل
المجلد وشغّل:

```
./render.sh
```

والفيديو النهائي هو `output.mp4` داخل المجلد نفسه. الحزمة
مكتفية بذاتها: فيها المشروع وكل ملفات الوسائط ونسخة من كود
AgentCut والخطوط، ولا تحتاج شبكة ولا خادم MCP ولا نسخة
المستودع.

## الطريقة الثانية: المستودع الكامل على الهاتف

إن أردت تشغيل AgentCut كاملا على الهاتف (أوامر `validate`
و`render` و`serve` من المستودع نفسه):

```
pkg install git python ffmpeg
git clone <رابط المستودع>
cd agentcut
sh scripts/setup-termux.sh
```

والسكربت خامل التكرار (آمن أن يُشغَّل مرتين): يثبّت الحزم،
ويتحقق من إصداري python وffmpeg ومن مرشحات drawtext وxfade
وloudnorm (وvidstab اختياري)، وينسخ الخطوط المضمّنة إلى
`~/.agentcut-fonts` ويثبّت متغيرها في `~/.bashrc` مرة واحدة،
ثم يجري اختبار دخان: مقطع ثانية واحدة بسطر عربي، لإثبات
أن python وffmpeg وdrawtext والخط العربي تعمل كلها.

## ما يجب أن تتوقعه بصراحة

- التصيير يستهلك المعالج بث intensity: الهاتف سيسخن، وقد
  يخفّض سرعته بالحرارة في التصييرات الطويلة، ولن يطابق سرعة
  الخادم السحابي. ابدأ بمشاريع قصيرة.
- أبقِ الهاتف على الشحن وTermux في الواجهة أثناء التصيير:
  أندرويد قد يقتل العمل في الخلفية، ومهام MCP المنفصلة
  (التي تبقى بعد إغلاق الاتصال) غير موثوقة على الهاتف
  لهذا السبب — حزم التصيير تعمل في الواجهة عمدا.
- أبقِ الحزمة داخل مجلد Termux الرئيسي، لا على بطاقة SD.
- خادم MCP على الهاتف ممكن تقنيا داخل Termux، لكن تطبيق
  Muse لا يتصل بخوادم MCP تعمل على جهازك، لذلك سير العمل
  على الجهاز هو سطر الأوامر فقط، لا MCP.

## كيف يجد التصيير الخطوط (ترتيب الاكتشاف)

1. متغير البيئة `AGENTCUT_FONT_DIR` (مجلد خطوطك أنت).
2. مجلد `fonts/` المضمّن في المستودع أو في الحزمة.
3. مجلدات خطوط Termux تحت `$PREFIX/share/fonts/...`.
4. مسارات نظام لينكس `/usr/share/fonts/...`.

وإن كان المشروع فيه نص عربي ولم يُعثر على خط عربي في أي
مكان، يفشل التحقق بخطأ منظّم `FONT_NOT_FOUND` يذكر الحل،
ولا يُصيَّر أبدا بصناديق حروف مفقودة صامتة. والمشروع الذي
فيه نص لاتيني فقط يحتاج خطا لاتينيا بالطريقة نفسها.

## افتراضات لينكس التي أُصلحت لهذا الإصدار

- الخطوط كانت بمسارات مطلقة تحت `/usr/share/fonts` فقط:
  غير موجودة على Termux. صارت بالترتيب أعلاه.
- فحص الخطوط كان يطلب DejaVu لأي نص: مشروع عربي خالص
  كان يفشل على جهاز فيه Noto فقط رغم قابليته للتصيير،
  ومشروع عربي مع DejaVu فقط كان يجتاز التحقق ثم يُصيَّر
  صناديق فارغة. صار الفحص لكل نص حسب خطّه هو.
- المسارات المطلقة في المشاريع تنكسر عند نقلها: الحزمة
  تعيد كتابة كل مرجع إلى مسار نسبي داخل `media/`.
- الملفات المؤقتة تحترم `TMPDIR`، والمخرج الذري يكتب
  الملف المؤقت في مجلد المخرجات نفسه، فيعملان داخل
  مجلد Termux الرئيسي.
- مرشح vidstab اختياري: موجود فقط عند طلب التثبيت،
  وسكربت الإعداد يبلّغ عن غيابه بدلا من إخفائه.

## استكشاف الأعطال

- `python3 not found`: نفّذ `pkg install python`.
- `ffmpeg not found`: نفّذ `pkg install ffmpeg`.
- `FONT_NOT_FOUND`: الحزمة فيها مجلد `fonts/`؛ تأكد أنك
  تشغّل `./render.sh` من داخل مجلد الحزمة نفسه، لا من
  خارجه، لأنه يضبط متغير الخطوط من موقعه هو.
- فشل تصيير برسالة FFmpeg: انسخ الرسالة كما هي إلى الوكيل.
- تصيير بطيء أو توقف: هذا غالبا خفض سرعة بالحرارة أو
  قتل أندرويد للعمل في الخلفية — أعد التشغيل في الواجهة
  والهاتف على الشحن، وابدأ بمشروع أقصر.

## بوابة الاكتمال المتبقية

التجربة الأولى على الهاتف لا يستطيع الوكيل أداءها بنفسه:
ثبّت Termux، ونفّذ `pkg install python ffmpeg`، وفكّ حزمة
مُسلَّمة، وشغّل `./render.sh` فيها، وبلّغ النتيجة. إلى أن
يحدث ذلك، يبقى العمل على الجهاز "مُسلَّما ومختبرا في
محاكاة" لا "مثبتا على الهاتف".
